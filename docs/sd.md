# SD 卡驱动流程（白话版）

本文不讲命令码和寄存器细节，先把 SD 卡从“上电”到“能读能写”的过程讲清楚。
具体代码在 `drivers/sd/`，分层和寄存器说明见 `docs/drivers.md`、`docs/fatfs.md`。

---

## 1. 先理解 SD 卡是什么

SD 卡不是一块可以直接按地址访问的内存，它内部有自己的控制器和状态机。

可以把它想成一个小设备：

```text
你发一条命令
它回一个响应
然后双方再搬数据
```

所以 SD 卡驱动不是简单 `memcpy`，而是：

```text
唤醒 → 确认 → 等就绪 → 认卡 → 分配地址 → 读容量 → 选中 → 提速 → 读写
```

---

## 2. 工程里的分层

```text
文件系统
  ↓
块设备适配层：把 SD 卡包装成 sd0
  ↓
SD 协议层：负责识别卡、读块、写块
  ↓
SDIO 硬件层：负责发命令、收响应、搬 FIFO 数据
  ↓
STM32F1 SDIO 外设
```

对应代码：

```text
drivers/sd/sd_blkdev.c       SD 卡 → 块设备
drivers/sd/sd.c              SD 协议
drivers/sd/sdio.h            主机控制器接口
drivers/sd/stm32f1_sdio.c    STM32F1 SDIO 实现
drivers/sd/sd_config.h       引脚和时钟
```

板级启动时只准备好 SDIO 通道，不立刻识别卡。
真正识别卡推迟到第一次读写，因为识别过程需要用到系统互斥量，而板级初始化阶段系统调度还没起来。

---

## 3. 初始化流程

### 第一步：上电，用很慢的速度通信

刚上电的卡不能用高速，先让卡稳定下来。

识别阶段通常用 400kHz 左右，实际代码还会在失败时退到 200kHz、100kHz，适应卡座接触电阻和走线差异。

### 第二步：让卡复位

先让卡回到初始待命状态，相当于告诉它：

```text
先别干别的，重新站好，准备接受询问。
```

### 第三步：询问卡支持什么电压、是不是新版本

确认这张卡能不能在当前板子上正常工作，以及它是不是支持高容量。

### 第四步：反复问卡“你准备好没有”

卡内部上电需要时间。
驱动会反复询问，直到卡明确表示“我已经准备好工作了”。

### 第五步：读取卡的身份信息

包括厂商、产品名、序列号、生产日期等。

这一步相当于：

```text
确认“你是哪张卡”。
```

### 第六步：给卡分配一个短地址

总线上可能不止一张卡，后面通信要用一个短地址来指定它。

可以理解为：

```text
给你编个号，后面叫号通信。
```

### 第七步：读取卡的容量参数

从卡里拿到容量信息，算出：

```text
这张卡总共有多少个 512 字节的块
```

后面读写的地址都用“第几个块”来表示。

### 第八步：选中这张卡

告诉卡：

```text
接下来就和你通信。
```

### 第九步：协商数据线宽度

先尝试用 4 根数据线并行传输。
如果失败，就退回 1 根数据线，保证还能用，只是速度慢一些。

### 第十步：提高通信速度

识别阶段用低速，确认卡正常后，切到正常工作速度。

当前代码使用 24MHz。

### 第十一步：初始化完成

到这里，卡已经知道自己的地址、容量、总线宽度，主机也知道怎么和它通信。
后面就可以按块读、按块写了。

### 初始化一句话总结

```text
先低速唤醒卡，确认电压和版本，等它上电完成，
读取身份和容量，分配地址并选中它，
最后切换总线宽度、提高速度。
```

## 4. 读流程

### 第一步：确保卡已经初始化

如果之前没识别过卡，会先补一次初始化。

### 第二步：独占 SD 总线

一次读写期间不允许别的线程同时操作卡，否则卡的状态机会乱。

### 第三步：检查要读的块号是否越界

比如卡总共有 1000 个块，就不能读第 1000 号块。

### 第四步：告诉卡“按 512 字节一块来”

老式小容量卡需要显式设置块长度。
大容量卡固定 512 字节一块，不需要这一步。

### 第五步：先把接收通道准备好

这一步很关键。

卡收到读命令后，响应一结束就会立刻开始送数据。
如果主机还没准备好接收，前面的数据就丢了。

所以顺序是：

```text
先准备接收 → 再告诉卡“我要读”
```

### 第六步：告诉卡要读哪个块

单块读就发单块命令，多块读就发多块命令。

老式小容量卡给的是字节地址，大容量卡给的是块号。
驱动内部会按卡的类型换算好。

### 第七步：卡开始送数据，主机从 FIFO 搬到内存

SDIO 内部有一个很小的 FIFO，只有 128 字节。

主机不断检查：

```text
FIFO 里有没有足够的数据？
有 → 一次搬 8 个字到内存
没有 → 等一会儿
出错 → 停止
```

### 第八步：多块读要明确告诉卡“停”

如果是连续读多块，读完要发停止命令，让卡回到正常状态。

### 第九步：释放 SD 总线

读完成，别的线程才能继续用卡。

### 读流程一句话总结

```text
先确认卡和地址，准备好接收通道，
再告诉卡读哪个块，卡送数据，
主机从 FIFO 搬到内存，最后停止并释放总线。
```

## 5. 写流程

### 第一步：确保卡已经初始化，并独占总线

和读一样。

### 第二步：检查块号是否越界

和读一样。

### 第三步：老式小容量卡设置块长度

大容量卡固定 512 字节，不需要。

### 第四步：先告诉卡“我要写哪个块”

写和读的顺序是反的：

```text
先发写命令 → 再准备发送数据
```

原因后面单独解释。

### 第五步：准备发送通道，并先塞一点数据

SDIO 的 FIFO 很小，卡在命令响应后很快就要数据。

如果 FIFO 是空的，马上就会报“发送来不及”。

所以驱动会先往 FIFO 里预填 128 字节，给 CPU 争取启动时间。

### 第六步：继续把剩下的数据写进 FIFO

主机不断检查：

```text
FIFO 有没有空位？
有 → 一次写 8 个字
没有 → 等一会儿
出错 → 停止
```

### 第七步：多块写要告诉卡“停”

和读一样。

### 第八步：等卡内部真正写完

数据进了卡的缓冲区，不代表已经写进 Flash。

卡内部还需要时间编程。
驱动会反复询问卡的状态，直到它回到“可以继续传数据”的状态。

不等这一步的话，紧接着读可能会读到旧数据。

### 第九步：释放 SD 总线

### 写流程一句话总结

```text
先确认卡和地址，告诉卡写哪个块，
准备发送并预填一点数据，
继续把剩余数据写进去，
最后停止、等卡内部写完、释放总线。
```

---

## 6. 为什么读和写的顺序不一样

### 读

```text
先准备接收 → 再发读命令
```

因为卡收到读命令后，响应一结束就立刻开始送数据。
接收通道没准备好，数据就丢了。

### 写

```text
先发写命令 → 再准备发送
```

因为如果提前准备发送，卡响应一到，主机就开始往外打数据，但 FIFO 还是空的，立刻就会“发送来不及”。

所以：

```text
读：先准备，后命令
写：先命令，后准备
```

## 7. FIFO 和“搬数据”到底在做什么

SDIO 内部有一个 32 个字、也就是 128 字节的小队列。

读的时候：

```text
卡 → FIFO → 内存
```

写的时候：

```text
内存 → FIFO → 卡
```

CPU 不需要自己维护队列下标。
每次读那个数据端口，硬件就自动弹出一个字；
每次写那个数据端口，硬件就自动压入一个字。

驱动只负责：

```text
看 FIFO 状态
一次搬 8 个字
数还剩多少
等全部完成
```

---

## 8. 几个实际注意事项

### 1. 数据搬运期间会短暂关中断

FIFO 只有 128 字节，如果搬到一半被别的线程抢走，读会溢出、写会断流。

所以数据阶段会短暂关中断，搬完再恢复。

### 2. 缓冲区要 4 字节对齐

SDIO 按 32 位搬运。
文件系统传下来的缓冲区不一定对齐，所以块设备层准备了一个 512 字节的跳板缓冲：
不对齐时先搬到跳板，再和卡交互。

### 3. 4 位总线失败会自动退回 1 位

4 位更快，但对走线和 CPU 搬运速度要求更高。
切不过去就退回 1 位，功能不受影响。

### 4. 写完要等卡内部编程完成

写命令返回只代表数据进了卡的缓冲区。
不等它真正写完，紧接着读可能读到旧内容。

### 5. 没有卡或接触不良时先降速重试

识别阶段会从高速往低速退，接触电阻大、走线长时低速更容易成功。

## 10. 一句话总结

```text
初始化：低速唤醒、确认、等就绪、认卡、分配地址、读容量、选中、提速。
读：先准备接收，再让卡读，卡送数据，主机搬进内存。
写：先让卡写，再准备发送并预填，继续搬数据，最后等卡内部写完。
```
